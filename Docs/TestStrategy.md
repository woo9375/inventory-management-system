# Test Strategy — 호텔 재고 관리 시스템

---

## 테스트 레이어

### 1. Unit Test
비즈니스 로직 함수의 입출력 검증.

**대상**: StockEngine.gs, RBAC.gs, Archive.gs 핵심 함수

**핵심 테스트 시나리오**:
- 재고 수량: 초기재고 + 입고 - 출고 - 폐기 = 정확한 현재고
- 단가 스냅샷: 입고 시점의 매입단가 정확히 복사
- FIFO 차감: 가장 오래된 로트부터 정확히 차감
- 시즌 배수: 성수기 배수 정확히 반영
- 비밀번호: 해싱 → 검증 → 일치/불일치

### 2. Business Logic Test
업무 규칙 준수 여부 검증.

**핵심 테스트 시나리오**:
- 월마감 FIFO 이월: 로트별 단가 유지
- 안전재고 계산: 일평균 × 안전재고일수 × 시즌배수
- 발주점 계산: 일평균 × 리드타임 + 안전재고
- 미사용 품목: 대시보드/검색에서 제외
- 거래ID 확정 후 구분 변경 차단

### 3. Integration Test
모듈 간 연동 검증.

**핵심 테스트 시나리오**:
- API 인증: 모든 엔드포인트의 `validateSession()` 동작
- 권한 검증: Admin/Manager/Staff별 접근 제어
- 캐시: 데이터 변경 → `invalidateAll()` → 재조회 시 최신 데이터
- 동시성: LockService로 동시 입출고 차단

### 4. E2E Test (Playwright)
실제 Web App에서의 사용자 시나리오 검증.

**핵심 테스트 시나리오**:
- 로그인 → 대시보드 표시 (Admin)
- 로그인 → 입출고 화면 (Staff)
- 품목 등록 → 검색 → 수정 → 비활성화
- 입출고 등록 → 최근 기록 조회
- 업장 추가 → 시트 생성 확인
- 비밀번호 변경

### 5. Human QA
배포 후 실제 업무 환경에서의 최종 검증.

**핵심 검증 항목**:
- 실제 업무 흐름대로 입출고 가능
- 대시보드 수치 정확성
- 모바일 UI 사용성
- 권한별 접근 정상

## 현재 상태

> 최종 갱신: TASK-004 (DEV 환경 연결 및 E2E 인프라 구축)

| 테스트 유형 | 상태 | 실행 방법 |
|-------------|------|-----------|
| Unit Test (로직 시뮬레이션) | ⚠️ 부분 구현 | `npm run test:unit` |
| Business Logic Test | ❌ 미구현 | — |
| Integration Test | ❌ 미구현 | — |
| E2E Test (Playwright) | ⚠️ 인프라 완료 / 실행 차단 | `npm run test:e2e` |
| DEV 환경 검증 | ✅ 구현 | DEV Apps Script에서 `verifyDevEnvironment()` |
| Human QA | ✅ 수동 수행 중 | — |

### Unit Test 범위 (현재)
`tests/unit/*.test.js` — GAS 코드는 Node에서 직접 실행할 수 없으므로,
`src/*.gs`의 핵심 로직 블록을 Node로 옮기고 Sheets API를 모킹한 **로직 시뮬레이션**이다.
실제 GAS 런타임 동작 보장은 아니며, 그 역할은 DEV E2E가 담당한다.

- `migration-v11.test.js` — 단위 마이그레이션 치환/멱등성 (TASK-002)
- `onedit-changelog.test.js` — 변경이력 다중 셀 처리 12개 시나리오 (TASK-003)

### E2E Test 현재 제약
DEV Web App 배포가 **Google 계정 로그인을 요구**하여 자동 실행이 차단되어 있다.
해소 방법은 `Docs/DevEnvironment.md` 7절 참고 (`save-auth-state.js`로 세션 1회 저장).
환경변수가 없으면 테스트는 **skip** 되며, 미실행 테스트가 통과로 집계되지 않는다.

## 향후 구축 방향

1. ~~**1단계**: Unit Test 작성~~ → 부분 완료 (로직 시뮬레이션)

4. **4단계**: CI/CD에 테스트 통합 (GitHub Actions)
