## 2. 재고 출고

| 규칙 | 설명 |
|------|------|
| 구분 | "출고" |
| 수량 검증 | 거래 입력 수량은 **양수만 허용** (`qty > 0`). 단, 가용 재고를 초과하는 출고는 허용되며 결과적으로 현재고가 음수가 될 수 있다 |
| **음수 재고 표시** | 초과 출고로 현재고가 음수가 되면 **음수 그대로 표시한다**(`-5`). 선출고 후입고·실사 결손 수량을 현업이 파악해야 하기 때문이며, 과거처럼 0으로 눌러 표시하지 않는다 (TASK-011) |
| 음수 재고의 의미 | "미입고(전표 누락)" 또는 "실물 결손"을 뜻하는 조치 필요 신호다. 품목 마스터 H열과 웹앱(품목 마스터·대시보드)에 붉은색으로 강조된다 (TASK-011) |
| **재고자산 0원 하한** | 수량은 음수를 허용하되 재고 합계금액(W열)은 **0원 미만이 될 수 없다**. 마이너스 자산이 장부에 기록되면 회계 기준 위반이므로 `현재고 <= 0`이면 평가액은 0원으로 고정한다 (TASK-011) |
| 음수 재고와 월마감 | 음수 재고 품목이 하나라도 남아 있으면 **월마감이 차단된다** (제10조 참조) (TASK-011) |
| 출고 일평균 | 최근 30일 또는 시즌 기간 내 출고 수량으로 일평균 산출 |
| 단가 스냅샷 | 품목 마스터 단가가 아닌 **실제 소진 로트의 입고단가**를 기록 (FIFO) |
| 다중 로트 분할 | 출고 수량이 2개 이상 로트에 걸치면 로트별로 행을 나누어 저장 (제8조 참조) |

## 6. 발주

### 발주점 (ROP) 계산
```
발주점 = 일평균사용량 × 리드타임 + 안전재고
```
- ARRAYFORMULA로 자동 계산

### 안전재고
```
안전재고 = 일평균사용량 × 안전재고일수 × 시즌배수
```

### 적정발주량
```
적정발주량 = 일평균사용량 × 목표유지일수 - 현재고
```
- **일평균사용량이 0 이하이면 적정발주량은 항상 0** — 사용 이력이 없는 품목은 현재고가 음수여도 발주를 권장하지 않는다. `0 - (-5) = 5`가 허수 발주로 이어지던 문제를 막는다 (TASK-011)
- 계산 결과가 음수이면 0으로 절사한다

### 발주서 생성
`[검토 필요]` — 발주점/적정발주량 계산은 있으나, 실제 발주서 생성 기능은 미구현.

## 8. 로트 (Lot) / FIFO

| 규칙 | 설명 |
|------|------|
| 로트 구분 | 각 입고 건이 하나의 로트 (날짜 + 수량 + 단가) |
| 출고 차감 | 가장 오래된 로트부터 선입선출 차감 |
| 초기재고 | FIFO에서 가장 오래된 로트(date=0)로 취급 |
| 잔여 금액 | 각 로트의 `잔여수량 × 단가` 합산 |

### 8-1. 다중 로트 분할 저장 (Parent-Child)

출고/폐기 1건이 여러 로트에 걸칠 때, 장부(업장 시트)에도 로트 단위로 나누어 기록합니다.
사용자는 1회 등록하지만 시스템이 자동으로 N개 행을 생성합니다.

| 규칙 | 설명 |
|------|------|
| 적용 대상 | "출고", "폐기" (입고는 항상 1행) |
| 분할 기준 | 등록 시점의 미소진 잔여 로트를 FIFO 순서로 소진 (초기재고 → 오래된 입고 순) |
| 행별 단가 | 각 행에 해당 로트의 실제 입고단가를 스냅샷 |
| 거래ID | 공통 Parent ID + 2자리 인덱스 (`FB-20260831-A1B2C3D4-01`, `-02`, …) |
| 비고 | 2개 이상 분할 시 사용자 비고 뒤에 `[FIFO N/총분할수, 로트일자: YYYY-MM-DD]` 자동 부착 |
| 초기재고 로트 | 로트일자를 `초기재고`로 표기 |
| 초과 출고 | 가용 로트 총량 부족 시 잔여 수량은 **현재 마스터 매입단가**로 마지막 행 생성, 비고에 `[FIFO 초과출고]` 부착 |
| 저장 방식 | N개 행을 1회 `setValues()`로 배치 삽입 (`LockService` 잠금 구간 내) |
| 시트 구조 | 9열 구조(`TX_COLS`) 유지 — 열 추가 없음 |

## 10. 월마감

| 규칙 | 설명 |
|------|------|
| 실행 | Admin만 가능 (`executeMonthlyClosing()`) |
| 동시성 | LockService로 다른 작업 차단 |
| 아카이브 | 마감 대상 데이터를 Google Drive 별도 스프레드시트로 이관 |
| FIFO 이월 | 잔여 로트를 "입고" 거래로 다음 달에 이월 (로트별 단가 유지) |
| 이월 거래ID | `SYS-{YYYYMMDD}-{UUID8}` 형식 |
| 초기재고 리셋 | 마감 후 품목 마스터의 초기재고를 0으로 리셋 (이중 카운팅 방지) |
| 리셋 순서 | 초기재고 리셋을 이월 행 삽입보다 **먼저** 수행 — 중간 실패 시 이중 카운팅이 남지 않도록 (TASK-006) |
| 이중 계상 감지 | 마감 직후 `초기재고 > 0` + "마감 이월" 입고 행이 함께 있으면 경고 로그 기록 (자동 교정은 하지 않음) |
| 초기재고 보호 | 품목 마스터 G열에 경고 전용(warning-only) 보호 — 마감 후 수동 입력 실수를 차단하되 신규 품목 등록 시 입력은 계속 가능 |
| 업장 시트 정리 | 마감 대상 행은 통합 시트뿐 아니라 **업장 시트에서도 제거** — 통합 시트는 업장 시트로부터 재구성되는 파생 뷰이므로, 남겨두면 재취합 시 마감이 무효화된다 (TASK-006) |
| 이월 행 보존 | 재취합(`consolidateAllSheets`)은 통합 시트의 `마감 이월` 행을 지우지 않는다 |
| 아카이빙 단일화 | 월마감 아카이브는 **수동 월마감(`executeMonthlyClosing()`) 단일 경로**로만 생성된다. 시간 기반 자동 아카이빙(`archiveOldRecords()`)은 폐기 — 미검증 데이터를 복사하고 보관 저장소를 이원화하는 문제가 있었다 (TASK-008) |
| 마감 기준일 기록 | 마감 성공 시 마감월 말일을 `ScriptProperties.LAST_CLOSED_CUTOFF`(yyyy-MM-dd)에 기록. 값이 없으면 통합 시트의 `마감 이월` 행(익월 1일)에서 하루를 빼 역산한다 (TASK-010) |
| **마감월 소급 수정 금지** | 마감 기준일 **이하** 날짜의 입출고는 등록·수정할 수 없다. **Super Admin을 포함해 역할 예외 없음.** 마감은 회계 기간의 장부를 동결하는 행위이며, 마감 원장은 이미 별도 스프레드시트로 분리되고 잔여 로트는 이월 행으로 스냅샷되어 있어 소급 입력 시 FIFO 체인이 이월분과 이중 계상된다 (TASK-010) |
| 차단 지점 | ① 웹앱 `addTransaction()` ② 업장 시트 A열(날짜) 직접 편집 `onEdit` ③ 거래 등록 폼 날짜 `min` 속성. ①이 1차 방어이고 ②③은 우회 경로 차단·UX 보조다 (TASK-010) |
| 과거 오류 정정 방법 | 마감월 데이터를 고치지 않고 **당월에 재고조정 거래를 등록**한다. 감사 추적성(Audit Trail)을 유지하기 위함 (TASK-010) |
| 마감 이월 행 보호 | 통합 시트의 이월 행(거래ID `SYS-…`)을 직접 편집하면 `onEdit`이 되돌리고 경고한다 (TASK-010) |
| 마감 이력 없음 | `LAST_CLOSED_CUTOFF`도 이월 행도 없으면 차단하지 않는다 — 신규 도입 환경에서 모든 날짜 입력이 막히지 않도록 (TASK-010) |
| **음수 재고 시 마감 차단** | 현재고가 음수인 품목이 1건이라도 있으면 마감을 **즉시 중단**한다. 마감은 과거 내역을 아카이브로 잘라내고 잔여 로트(`remaining > 0`)만 이월하므로, 음수 상태로 마감하면 결손 수량이 흔적 없이 `0`으로 둔갑해 영구 유실된다. 누락 입고 전표 등록 또는 실사 조정을 마친 뒤 재시도해야 한다 (TASK-011) |
| 음수 판정 기준 | 마스터 H열(현재고)의 **기록값**과 `초기재고 + 입출고 실적`으로 **재계산한 값** 중 하나라도 음수면 차단한다 — H열이 마지막 재계산 이후 값이라 최신이 아닐 수 있기 때문이다. 미사용(`X열 = 미사용`) 품목은 실사 대상이 아니므로 제외한다 (TASK-011) |

## 17. 감사 이력 (Audit Trail)

| 항목 | 방식 |
|------|------|
| 품목 변경이력 | `SHEET_CHANGELOG` — 자동 기록 (onEdit + API) |
