# Business Rules — 호텔 재고 관리 시스템

> 이 문서는 현재 코드에서 확인된 업무 규칙을 정확히 기록합니다.
> 확인되지 않은 항목은 `[검토 필요]`로 표시합니다.

---

## 1. 재고 입고

| 규칙 | 설명 |
|------|------|
| 등록 경로 | 업장별 시트에서 직접 입력 또는 Web App API |
| 필수 항목 | 날짜, 품목코드, 구분("입고"), 수량 |
| 자동 항목 | 품목명(마스터 조회), 단가(매입단가 스냅샷), 거래ID |
| 수량 제약 | 0 초과, 최대 1억(`MAX_TRANSACTION_QTY`) |
| 날짜 형식 | `YYYY-MM-DD` |
| 품목코드 검증 | 마스터에 등록되고 "사용" 상태인 품목만 허용 |
| 단가 스냅샷 | 입고 시점의 품목 마스터 매입단가를 자동 복사하여 거래 기록에 보존 |

---

## 2. 재고 출고

| 규칙 | 설명 |
|------|------|
| 구분 | "출고" |
| 수량 검증 | 양수만 허용, 음수 재고 발생 시 현재고가 0으로 처리됨 |
| 출고 일평균 | 최근 30일 또는 시즌 기간 내 출고 수량으로 일평균 산출 |

---

## 3. 폐기

| 규칙 | 설명 |
|------|------|
| 구분 | "폐기" |
| 재고 차감 | 출고와 동일하게 재고에서 차감 |
| FIFO 영향 | 출고와 동일하게 가장 오래된 로트부터 차감 |

## 5. 재고 조정
`[검토 필요]` — 별도의 재고 조정 기능은 확인되지 않음. 초기재고 필드를 통한 간접 조정만 존재.

## 6. 발주

### 발주점 (ROP) 계산
```
발주점 = 일평균사용량 × 리드타임 + 안전재고
```
- ARRAYFORMULA로 자동 계산

### 안전재고
```
안전재고 = 일평균사용량 × 안전재고일수 × 시즌배수
```

### 적정발주량
```
적정발주량 = 일평균사용량 × 목표유지일수 - 현재고
```

### 발주서 생성
`[검토 필요]` — 발주점/적정발주량 계산은 있으나, 실제 발주서 생성 기능은 미구현.

---

## 7. 안전재고

| 항목 | 설명 |
|------|------|
| 기본 산출 | `일평균 × 안전재고일수 × 시즌배수` |
| 시즌 배수 | 성수기일 때 배수 적용 (예: 1.5배) |
| 비수기 배수 | 1.0 (기본) |
| 최소 분석일수 | 7일 (`MIN_ANALYSIS_DAYS`) — 시즌 시작 7일 미만이면 30일 평균으로 fallback |

---

## 8. 로트 (Lot) / FIFO

| 규칙 | 설명 |
|------|------|
| 로트 구분 | 각 입고 건이 하나의 로트 (날짜 + 수량 + 단가) |
| 출고 차감 | 가장 오래된 로트부터 선입선출 차감 |
| 초기재고 | FIFO에서 가장 오래된 로트(date=0)로 취급 |
| 잔여 금액 | 각 로트의 `잔여수량 × 단가` 합산 |

---

## 9. 단가

| 항목 | 설명 |
|------|------|
| 매입단가 | 품목 마스터의 T열 (`MASTER_COLS.UNIT_PRICE`) |
| 과세구분 | "과세" / "면세" (`MASTER_COLS.TAX_TYPE`) |
| 공급단가 | 수식 자동 계산 |
| 단위 세액 | 수식 자동 계산 |
| 거래 시 단가 | 입출고 시점의 매입단가 스냅샷 (거래 기록에 고정) |

---

## 10. 월마감

| 규칙 | 설명 |
|------|------|
| 실행 | Admin만 가능 (`executeMonthlyClosing()`) |
| 동시성 | LockService로 다른 작업 차단 |
| 아카이브 | 마감 대상 데이터를 Google Drive 별도 스프레드시트로 이관 |
| FIFO 이월 | 잔여 로트를 "입고" 거래로 다음 달에 이월 (로트별 단가 유지) |
| 이월 거래ID | `SYS-{YYYYMMDD}-{UUID8}` 형식 |
| 초기재고 리셋 | 마감 후 품목 마스터의 초기재고를 0으로 리셋 (이중 카운팅 방지) |
| 자동 아카이빙 | `archiveOldRecords()` — 매월 1일 트리거, 이전 달 데이터를 연도별 스프레드시트로 이관 |

---

## 11. 이월

| 규칙 | 설명 |
|------|------|
| 이월 대상 | 월마감 후 FIFO에서 남은 로트 |
| 이월 방식 | 각 로트를 별도 "입고" 거래로 기록 |
| 담당자 | "System" |
| 비고 | "{년}년 {월}월 마감 이월" |

---

## 12. 사용자 / 역할

| 역할 | 설명 |
|------|------|
| admin | 전체 시스템 관리, 사용자 관리, 월마감 |
| manager | 품목 마스터 관리, 전체 업장 조회, CSV 업로드 |
| staff | 담당 업장 입출고만 |

---

## 13. 업장 (Location)

| 규칙 | 설명 |
|------|------|
| 분류 | 호텔, 콘도, 빌리지, 스파월드 등 |
| 태그 | 영어 대문자 2~3자 (거래ID 접두사) |
| 시트 | 업장별 전용 시트 자동 생성 (템플릿 복사) |
| 상태 | "대기" → "생성완료" → "삭제됨" |
| 삭제 | 소프트 삭제 (시트 숨김 + 상태 변경) |

## 15. 데이터 수정

| 규칙 | 설명 |
|------|------|
| 품목 마스터 수정 | Admin/Manager만 가능, 변경이력 자동 기록 |
| 거래 구분 수정 | 거래ID 발급 후 구분(D열) 변경 차단 |
| 자동 계산 열 | C(품목명), F(단가), I(거래ID) 직접 편집 차단 |
| 생성완료 업장명 | 변경 불가 |

---

## 16. 데이터 삭제

| 규칙 | 설명 |
|------|------|
| 품목 삭제 | 물리 삭제 없음, "미사용" 처리 (소프트 삭제) |
| 업장 삭제 | 물리 삭제 없음, 시트 숨김 + "삭제됨" 상태 |
| 사용자 삭제 | clearContent()로 처리 |
| 거래 삭제 | `[검토 필요]` — Web App에서의 거래 삭제 기능은 확인되지 않음 |

---

## 17. 감사 이력 (Audit Trail)

| 항목 | 방식 |
|------|------|
| 품목 변경이력 | `SHEET_CHANGELOG` — 자동 기록 (onEdit + API) |
| 시스템 에러 | `SHEET_SYSTEM_LOGS` — `_logError()` |
| 입출고 추적 | 거래ID를 통한 개별 추적 |
| CSV 백업 | 수동 또는 관리자 메뉴에서 실행 |
