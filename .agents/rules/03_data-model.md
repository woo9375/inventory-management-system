# Data Model & Schema Rules (SSOT)

이 문서는 AI가 Google Sheets를 데이터베이스로 사용할 때 준수해야 할 **데이터 무결성 제약 사항**만 정의합니다.

> **물리적 시트 구조(열 이름, 타입, 제약조건)는 `Docs/SheetSchema.md`를 참조하십시오.**
> **논리적 엔티티 간 관계와 설계 목적은 `Docs/DataModel.md`를 참조하십시오.**

## 절대 금지 및 필수 원칙
1. **스키마 임의 추측 금지**: AI는 코드를 작성할 때 시트의 열(Column) 번호나 구조를 스스로 추측해서는 안 됩니다. 반드시 `Config.gs`의 상수와 `Docs/SheetSchema.md`를 기준으로 작업하십시오.
2. **참조 무결성 유지**: 트랜잭션 기록의 `품목코드`는 항상 마스터 시트에 존재하는 활성 식별자여야 합니다. 데이터 삭제/수정 시 다른 엔티티의 참조가 깨지지 않도록 하십시오.
3. **Primary Key 보호**: 거래 ID, 품목 코드, 업장 태그 등 기본 키(PK) 성격을 띠는 값은 발급 후 변경이 불가능하게 시스템적으로 보호되어야 합니다.
4. **시트 구조 임의 변경 불가**: 기존 운영 중인 시트의 구조(열 순서 변경, 삭제)는 다른 수식 및 스크립트에 치명적 영향을 줍니다. 스키마 변경이 필요한 경우 반드시 설계(Plan) 후 승인을 거쳐 `Docs/SheetSchema.md`와 `Migration.gs`를 참조하여 수행하십시오.
