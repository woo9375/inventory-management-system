# 호텔 재고 관리 시스템 v1.0.0
> Google Apps Script 기반 통합 구매/재고 관리 웹 애플리케이션

---

## 📌 1. 프로그램 개요 및 목적
호텔의 소모품 및 자재 입출고, 재고 관리, 자동 발주점 계산, 시즌별 안전재고 조절을 하나의 시스템으로 완벽하게 통합 관리하는 솔루션입니다. 
각 업장에서 입력한 데이터가 중앙으로 자동 취합되며, 정확한 재고 자산 평가를 위해 선입선출(FIFO) 기반의 월 마감 기능을 제공합니다.

---

## 👥 2. 사용자별 권한 및 역할 (RBAC)
본 시스템은 직무에 따라 화면과 권한이 다르게 노출됩니다.

1. **최고 관리자 (Admin)**: 시스템 설정, 사용자 계정 생성, 권한 부여, 신규 업장 시트 생성, 시스템 데이터 수동 백업 및 월 마감 실행 권한을 갖습니다.
2. **구매 총괄 / 매니저 (Manager)**: 품목 마스터(신규 자재) 등록 및 수정, 전 업장의 통합 대시보드 조회, 대량 CSV 업로드, 전체 입출고 내역 열람이 가능합니다.
3. **각 업장 담당자 (Staff)**: 본인이 소속된 업장의 입출고 내역 입력 및 조회만 가능하며, 품목 마스터 수정이나 시스템 설정에는 접근할 수 없습니다.

## 💡 3. 핵심 비즈니스 로직 이해하기 (필독)
시스템을 정확하게 사용하기 위해 실무자 및 제작자가 반드시 알아야 할 3가지 핵심 구조입니다.

### ① 🗓️ 월 마감과 선입선출 (FIFO) 로직
매월 말일, 시스템 관리자가 '월 마감'을 실행하면 한 달간의 입출고 기록이 구글 드라이브의 **'마감 데이터' 폴더 내 연도별 하위 폴더(예: `2026/[입출고마감]_2026_08`)로 분리**되어 안전하게 보관됩니다. 이때 **단순히 수량만 뭉뚱그려서 이월하지 않습니다.**

- **로트(Lot)별 분할 이월**: 10일에 1,000원에 10개 입고, 20일에 1,200원에 20개 입고된 사과가 있다고 가정합니다. 총 5개가 소비되었다면, 남은 재고는 25개입니다.
- 시스템은 이 25개를 하나로 합치지 않고, `1,000원짜리 5개`, `1,200원짜리 20개` 로 각각 **고유의 단가를 유지한 채 새로운 입고 기록으로 다음 달 메인 시트에 기록**합니다.
- 따라서 마감을 여러 번 진행해도 구매 단가가 섞이지 않으며 완벽한 **선입선출 기반의 재고 자산 평가**가 가능합니다.

### ② 📅 시즌별 안전재고 보정
호텔업의 특성상 성수기(여름, 겨울)와 비수기의 소모품 사용량이 크게 다릅니다.
- '시즌 관리' 메뉴에서 특정 기간(예: 7/15 ~ 8/15)을 '성수기'로 지정하고 **배수(Multiplier)**를 1.5로 설정할 수 있습니다.
- 해당 기간이 되면 대시보드의 모든 품목의 '안전 재고'와 '적정 발주량' 시스템 요구치가 자동으로 1.5배 상향 조정되어, 성수기 재고 부족 사태를 시스템이 선제적으로 방어합니다.

### ③ 📤 품목 마스터 CSV 대량 업로드
신규 품목 마스터 데이터를 대량으로 등록할 때 CSV 업로드 기능을 지원합니다.
- **필수 열 구조(11개 열)**: A열부터 순서대로 `품목코드`, `품목명`, `카테고리`, `규격`, `단위`, `초기재고`, `리드타임`, `안전재고일수`, `목표유지일수`, `과세구분`, `매입단가` 순서여야 합니다.
- 엑셀 파일을 업로드용으로 변환할 때, 기존 엑셀에 없는 항목(규격, 초기재고 등)은 빈칸이나 기본값(`C`, `0` 등)을 넣어서 순서와 개수를 맞춰준 뒤 **CSV(쉼표로 분리) 형식으로 저장**하여 웹앱에 업로드해야 합니다.

## 🚀 4. 배포 및 CI/CD 파이프라인 (제작자용)

본 프로젝트는 GitHub Actions를 통한 **자동화된 CI/CD 파이프라인**을 구축했습니다.
로컬 환경에서 `clasp push`를 직접 실행하지 않고, Git을 통한 버전 관리에 집중합니다.

### 1. 배포 방법
1. 변경 사항을 로컬 Git에 커밋합니다. (커밋 컨벤션: `[feat]`, `[fix]`, `[refactor]` 등)
2. `main` 브랜치에 코드를 `git push` 합니다.
3. GitHub Actions(`.github/workflows/clasp.yml`)가 변경 사항을 감지하고 자동으로 Google Apps Script에 배포(`clasp push --force`)합니다.

> ⚠️ **주의**: `.claspignore`에 명시된 파일(`*.md`, `node_modules/`, `backup/` 등)은 배포에서 제외됩니다. 소스 코드는 반드시 `src/` 폴더 내에 작성해야 합니다.

### 2. 시스템 초기화 (최초 1회)
1. Apps Script 에디터 접속 (`Code.gs`)
2. `createAll()` 함수를 수동 실행하여 데이터베이스 시트 뼈대 생성
3. 우측 상단 **[배포] -> [새 배포]** -> 웹 앱(Web App) 설정 후 링크 획득

## 🤖 5. AI 어시스턴트 (Antigravity) 연동 가이드

본 프로젝트는 AI 코딩 어시스턴트(Antigravity)가 프로젝트의 구조와 비즈니스 로직을 완벽하게 이해하고 코딩할 수 있도록 **맞춤형 규칙(Rules)**과 **자동화 스킬(Skills)**을 내장하고 있습니다.

프로젝트 루트의 `.agents/` 폴더에 다음 가이드가 포함되어 있습니다.

### 1. Rules (적용된 핵심 규칙)
AI가 코드를 작성/수정할 때 절대 어기지 않도록 강제된 프로젝트 제약사항입니다.
- **`01_gas-environment.md`**: Node.js API 사용 금지, `src/` 디렉토리 강제 등 Apps Script 환경 제약
- **`02_business-logic.md`**: 월 마감 시 FIFO 기반 단가 유지, 시즌별 안전재고 배수 보정 원칙
- **`03_rbac-policy.md`**: Admin/Manager/Staff 3단계 권한 체크 로직 강제
- **`04_code-conventions.md`**: 상수 `Config.gs` 집중 관리, 로깅 및 에러 핸들링 컨벤션

### 2. Skills (자동화 워크플로우)
AI에게 채팅창에서 다음과 같이 요청하면 정해진 파이프라인에 따라 작업을 수행합니다.
- **`gas-deploy` 스킬**: *"작업한 내용 배포해줘"* 라고 요청하면, `git add`, `commit`, `push`를 순서대로 수행하여 GitHub Actions CI/CD를 가동시킵니다.
- **`git-workflow` 스킬**: *"깃 워크플로우 알려줘"* 라고 요청하면, 커밋 컨벤션(`[feat]`, `[fix]`)과 브랜치 전략을 안내받을 수 있습니다.

## ❓ 6. 자주 묻는 질문 (FAQ)

### Q1. 웹앱에서 입출고 기록을 수정하거나 삭제할 수 없나요?
**의도된 설계입니다.** 과거 기록 조작 방지 및 데이터 무결성을 위해, 웹앱에서는 **'입력(신규 기록 생성)'만** 가능하도록 설계되어 있습니다.

- **오기입 시 대처법 ①** — 관리자(Admin)가 구글 스프레드시트에 직접 접속하여 해당 행을 수정하거나 삭제합니다.
- **오기입 시 대처법 ②** — 웹앱에서 **마이너스(-) 수량으로 상계 처리**합니다. 예를 들어 '사과 10개 입고'를 잘못 입력했다면, '사과 10개 출고'를 새로 기록하여 재고를 원복합니다.

> 💡 **Tip**: 상계 처리 시 비고(메모)란에 `"오기입 상계"` 등을 남기면 추후 감사 추적이 용이합니다.

### Q2. 수동 월마감 실행 시 "Google Drive API 권한" 오류가 뜹니다.
월마감 기능은 구글 드라이브에 마감 데이터를 백업 시트로 분리합니다. **최초 1회** 스크립트에 Drive 접근 권한을 승인해야 합니다.

1. 구글 시트에서 **[확장프로그램] → [Apps Script]** 로 이동합니다.
2. Apps Script 에디터에서 임의의 함수(예: `backupToCSV`)를 **1회 수동 실행** 합니다.
3. 브라우저 팝업으로 뜨는 **Google 권한 승인 창**에서 Drive API 접근을 허용합니다.
4. 이후 웹앱에서 월마감/CSV 백업이 정상 동작합니다.

### Q3. 웹앱이 느리게 반응하는 것 같아요 (로딩 스피너가 오래 표시됨).
정상적인 현상입니다. Google Apps Script 기반 웹앱은 모든 데이터 추가/수정/조회 시 **구글 서버와 HTTP 통신**이 필요하므로, 로딩 스피너가 **1~3초** 정도 표시될 수 있습니다.

- 데이터가 많은 품목 마스터나 대시보드 갱신 시에는 최대 5초까지 소요될 수 있습니다.
- 이는 Apps Script 런타임 환경의 고유한 제약이며, 데이터 손실과는 무관합니다.

### Q4. 담당자(Staff) 계정으로 로그인하면 일부 업장만 보입니다.
**RBAC(역할 기반 접근 제어)** 정책에 따라 설계된 정상 동작입니다.

- **Staff 권한**의 사용자는 관리자가 [계정 관리]에서 **배정한 업장만** 조회 및 입출고 조작이 가능합니다.
- 배정되지 않은 업장의 데이터에는 백엔드 레벨에서도 접근이 차단됩니다(IDOR 방어).
- 본인에게 배정된 업장 목록은 웹앱의 **[내 설정]** 탭에서 배지(Badge) 형태로 확인할 수 있습니다.
- 업장 배정 변경이 필요한 경우, Admin 권한의 관리자에게 요청하세요.

### Q5. '최근 입출고 내역'은 최대 몇 건까지 표시되나요?
- **최대 50건**이 업장별로 표시됩니다.
- **최신 등록일 기준 내림차순**(가장 최근 입력한 데이터가 맨 위)으로 정렬됩니다.

### Q6. 품목을 삭제하면 과거 거래 기록도 사라지나요?
아닙니다. 품목 마스터에서 삭제 버튼을 누르면, 해당 품목은 **물리적으로 삭제되지 않고 '미사용' 상태로 전환**됩니다. 과거 거래 내역은 그대로 보존되며, 품목 마스터 목록과 입출고 드롭다운에서만 노출이 중지됩니다.

## 💼 7. 운영 팁 & 주의사항

### 관리자(Admin)용
| 항목 | 설명 |
|------|------|
| **통합 갱신** | 구글 시트 메뉴 `[관리자 도구] → [통합 갱신]`을 실행하면 대시보드의 재고 현황·발주점·안전재고가 최신 데이터로 다시 계산됩니다. 웹앱에서도 동일한 버튼이 있습니다. |
| **신규내역취합** | 각 업장별 시트에 새로 기입된 최신 입출고 내역들만 빠르고 가볍게 중앙 데이터베이스(메인 시트)로 모아오는 기능입니다. 관리자가 실시간으로 재고 상황을 파악해야 할 때 사용합니다. |
| **시트 동기화 (새로고침)** | 웹앱의 각 탭(대시보드, 입출고 기록 등) 상단에 있는 `🔄 시트 동기화` 버튼을 누르면 캐시를 즉시 무효화하고 구글 시트의 최신 데이터를 웹앱으로 바로 불러옵니다. 웹앱 바깥(구글 시트)에서 직접 데이터를 수정한 후 웹앱에 반영할 때 사용합니다. |
| **CSV 백업** | 정기적으로 `[CSV 백업 실행]`을 통해 시스템 데이터를 구글 드라이브에 CSV 파일로 백업하세요. 스프레드시트 오류 시 복구 수단이 됩니다. |

### 📤 대량 데이터(CSV) 업로드 규칙
품목 마스터 탭에서 제공하는 CSV 업로드 기능을 통해 대량의 품목을 일괄 등록할 수 있습니다. 시스템의 안정성을 위해 다음 규칙들이 엄격하게 적용됩니다.

1. **데이터 파싱 순서**: 파일의 첫 번째 열부터 순차적으로 매핑됩니다. (권장: `품목코드`, `품목명`, `카테고리`, `규격`, `단위`, `초기재고`, `리드타임`, `안전재고일수`, `목표유지일수`, `과세구분`, `매입단가`)
2. **필수 항목**: `품목코드`(1열)와 `품목명`(2열)은 필수입니다. 누락 시 해당 행은 무시됩니다.
3. **중복 코드 무시**: 이미 시스템에 존재하는 품목코드와 동일한 코드가 포함된 행은 덮어쓰기 되지 않고 **건너뛰기(무시)** 처리됩니다.
4. **미등록 카테고리 업로드 차단 (All or Nothing)**: CSV 내 단 1개의 품목이라도 **'기초데이터' 탭에 등록되지 않은 카테고리**를 사용하고 있다면, 업로드가 그 즉시 중단되며 전체 데이터가 등록 실패 처리됩니다. 이때, 미등록 카테고리가 사용된 모든 품목코드 목록이 에러 메시지에 함께 출력되므로, 해당 카테고리를 기초데이터에 먼저 추가하시거나 오타를 수정 후 다시 업로드해야 합니다.
| **신규 업장 추가** | 웹앱에서 업장을 추가하면 자동으로 해당 업장의 입출고 시트가 생성됩니다. 구글 시트에서 별도로 시트를 만들 필요가 없습니다. |
| **권한 재동기화** | 사용자 계정이나 업장을 추가/삭제한 후에는 `[권한 재동기화]`를 실행하여 시트 보호 범위와 편집 권한을 갱신하세요. |

### 실무자(Staff)용

| **비밀번호 변경** | 웹앱 [내 설정] 탭에서 비밀번호를 직접 변경할 수 있습니다. 최소 4자 이상이어야 합니다. |
| **입출고 입력 시** | 품목명을 직접 타이핑하면 자동완성이 표시됩니다. 반드시 목록에서 선택하거나, 정확한 품목코드가 자동 입력되었는지 확인 후 저장하세요. |
| **수량 입력** | 수량은 반드시 **1 이상의 양수**로 입력해야 합니다. 0이나 음수는 시스템에서 자동 차단됩니다. |
| **오기입 처리** | 잘못 입력한 경우, 같은 품목에 대해 반대 구분(입고↔출고)으로 동일 수량을 입력하여 상계 처리하세요. |

### 시스템 제약사항
- **동시 편집**: 구글 시트 특성상 여러 사용자가 같은 업장 시트를 동시에 편집하면 충돌이 발생할 수 있습니다. 가능한 업장별 담당자를 명확히 지정하세요.
- **거래ID 불변**: 한 번 발급된 거래ID(`XX-YYYYMMDD-XXXXXXXX`)는 시스템이 자동 생성한 고유 식별자이며, 수동으로 변경할 수 없습니다.
- **자동계산 컬럼 보호**: 구글 시트에서 품목명(C열), 단가(F열), 거래ID(I열)은 시스템이 자동으로 채우는 컬럼입니다. 직접 편집 시 자동으로 원본 데이터로 복구됩니다.
- **캐시 갱신**: 품목 마스터나 업장 정보를 변경한 직후에는 약간의 지연(캐시 무효화 후 재로딩)이 있을 수 있습니다. 변경이 즉시 반영되지 않을 경우, 브라우저를 새로고침(F5)하세요.
